# Control protocol (app ⇄ core)

Ядро `claude-proxy-core` слушает **unix domain socket**:

```
~/Library/Application Support/ClaudeProxy/control.sock
```

Транспорт — **JSON Lines**: один JSON-объект на строку (`\n`), запрос → один ответ.
Соединение держится постоянным; приложение опрашивает `status` раз в ~2 с и шлёт команды по действию пользователя.

Ядро **не хранит** конфигурацию и ключи на диске. Приложение — источник правды:
активный профиль и приватный ключ клиента (из Keychain) передаются в команде `connect`/`switch`.
Приватный ключ живёт только в памяти ядра на время сессии и не логируется.

## Запрос

```json
{ "id": 1, "cmd": "<command>", ...params }
```

## Ответ

```json
{ "id": 1, "ok": true,  "result": { ... } }
{ "id": 1, "ok": false, "error": "human readable reason" }
```

## Команды

### `status`
Без параметров. Возвращает текущий `State` (см. ниже).

### `connect`
```json
{ "id": 2, "cmd": "connect", "profile": <Profile>, "privateKey": "<base64>" }
```
Поднимает туннель, ждёт handshake, запускает local proxy. Возвращает `State`
(уже `connected`, либо `error` с причиной). Долгая операция — ответ приходит по завершении.

**Лок ключа.** Первым шагом (до любых сетевых действий) ядро берёт эксклюзивный
неблокирующий `flock` на `<Application Support>/ClaudeProxy/locks/tunnel-<sha256(pubkey)[:16]>.lock`,
где `pubkey` выводится из `privateKey`; внутри файла — pid и путь control-сокета
владельца. Если ключ уже держит другой процесс `claude-proxy-core` (или другой
экземпляр), connect завершается `ok:false`, `State.state = "error"`, туннель не
поднимается:

```json
{ "id": 2, "ok": false,
  "error": "Этот ключ уже используется другим процессом claude-proxy-core (pid 12345, сокет /tmp/cpc-t.sock) — два подключения одним ключом ломают туннель",
  "result": { "state": "error", "lastError": "<тот же текст>", "forwardMode": "off", ... } }
```

Лок отпускается на `disconnect`, при ошибке подключения, при смене ключа и при
выходе процесса (в том числе `kill -9` — его снимает ОС, stale-локов нет). Повторный
connect/switch тем же ключом в том же процессе не самоблокируется. Невалидный
`privateKey` теперь отклоняется на этом же шаге (`невалидный приватный ключ клиента: …`).
Ошибка файловой системы при взятии лока (не занятость) подключение не блокирует —
только строка в логе.

### `disconnect`
Без параметров. Останавливает proxy и туннель. Возвращает `State` (`disconnected`).

### `switch`
```json
{ "id": 3, "cmd": "switch", "profile": <Profile>, "privateKey": "<base64>" }
```
Контролируемая смена сервера: перестать принимать соединения → закрыть туннель →
поднять новый → health check. При ошибке остаётся `error`, **без** прямого выхода в сеть.
Лок ключа — как у `connect` (та же ошибка, если ключ занят другим процессом).

### `healthcheck`
Без параметров. Выполняет проверку через туннель прямо сейчас, обновляет и возвращает `State`.

### `logs`
```json
{ "id": 4, "cmd": "logs" }
```
Возвращает `{ "lines": ["20:14:02 ...", ...] }` — технический лог (без секретов).

### `provision`
Автоматически разворачивает AmneziaWG-сервер по SSH и возвращает готовый endpoint.
Долгая операция (установка пакета — до пары минут): приложение ставит `recvTimeout` **240 с**.

```json
{
  "id": 5, "cmd": "provision",
  "clientPublicKey": "<base64, публичный ключ клиента для прокси>",
  "clientPublicKeyFull": "<base64, публичный ключ клиента для Полного VPN>",
  "ssh": {
    "host": "1.2.3.4", "port": 22, "user": "root",
    "password": "...", "privateKeyPath": "/path/id_ed25519", "passphrase": "..."
  },
  "provision": {
    "awgPort": 51820, "serverVpnAddress": "10.77.0.1",
    "clientVpnAddress": "10.77.0.2", "clientVpnAddressFull": "10.77.0.3",
    "jc": 5, "jmin": 50, "jmax": 1000, "s1": 64, "s2": 128,
    "h1": 1000001, "h2": 1000002, "h3": 1000003, "h4": 1000004
  }
}
```

- `ssh.password` и `ssh.privateKeyPath` оба опциональны, но **хотя бы одно** должно быть задано.
- `ssh.port` по умолчанию `22`, `ssh.user` — `root`.
- Сервер получает **два** клиентских peer'а с разными ключами — для бесшовного
  переключения без переусыновления:
  - `clientPublicKey` — peer прокси (запрошенный адрес `clientVpnAddress`, деф. `10.77.0.2`);
  - `clientPublicKeyFull` — peer Полного VPN (запрошенный `clientVpnAddressFull`, деф. `10.77.0.3`).
  `clientPublicKeyFull` **опционален**: если пуст или не задан — второй peer не добавляется.
- Блок `provision` можно слать целиком с дефолтами (как выше), частично или пустым —
  ядро подставит дефолты для незаданных полей.

**Режимы.** `fresh` — на сервере нет ни `/etc/amnezia/amneziawg/awg0.conf`, ни интерфейса
`awg0`: ставится пакет, генерятся ключи, создаётся конфиг из параметров запроса, `awg0`
поднимается. `adopt` (донастройка) — конфиг или интерфейс уже есть: пакет и серверные ключи
не трогаются, `[Interface]` не переписывается (параметры `awgPort`/`serverVpnAddress`/`jc…h4`
из запроса **игнорируются** и читаются с сервера), добавляются только peer'ы этого клиента:

- `awg0` поднят и `[Interface]` не менялся → peer'ы добавляются **вживую**
  (`awg set awg0 peer … allowed-ips …`) и дописываются в конфиг для ребута; перезапуска нет,
  сессии остальных клиентов не рвутся;
- `awg0` поднят, но пришлось изменить `[Interface]` (единственный случай — ненулевые `S3`/`S4`
  приводятся к `0`) → `awg0` перезапускается, в журнале — «существующие клиенты переподключатся»;
- конфиг есть, а `awg0` не поднят → интерфейс поднимается из конфига, ничего не удаляя.

nftables-таблица `claudeproxy` и `sysctl` перезаписываются, только если содержимое отличается.

**Выделение адресов** (одинаково в `fresh` и `adopt`, до любых правок конфига):

1. ключ клиента уже есть в конфиге (или в живом `awg show awg0 allowed-ips`) → его адрес
   переиспользуется: повторный `provision` того же клиента идемпотентен, конфиг байт в байт прежний;
2. иначе — запрошенный адрес, **если** он в подсети сервера и свободен;
3. иначе — наименьший свободный хост подсети.

Подсеть — из первого IPv4 `Address` секции `[Interface]` (без маски — `/24`). Заняты: адрес
сервера, сеть и broadcast, все `AllowedIPs` из конфига и с живого `awg0`. Прокси и Полный VPN
всегда получают разные адреса. Подсеть заполнена → `ok:false` с ошибкой
«выделение адреса клиенту: подсеть … заполнена…» (код скрипта 20), конфиг не изменён.

Ответ при `ok:true` — объект `provision.Result`:

```json
{
  "serverPublicKey": "...", "host": "...", "port": 51820,
  "serverVpnAddress": "10.77.0.1",
  "clientVpnAddress": "10.77.0.4", "clientVpnAddressFull": "10.77.0.5",
  "jc": 5, "jmin": 50, "jmax": 1000, "s1": 64, "s2": 128, "s3": 0, "s4": 0,
  "h1": 1000001, "h2": 1000002, "h3": 1000003, "h4": 1000004,
  "adopted": true, "log": ["шаг1", "шаг2", "..."]
}
```

- `clientVpnAddress` / `clientVpnAddressFull` — **фактические** адреса, выделенные сервером
  (могут отличаться от запрошенных); `clientVpnAddressFull` — пустая строка, если
  `clientPublicKeyFull` не передавался.
- `serverVpnAddress` — из `Address` конфига сервера, а не из запроса.

Приложение строит из него `Profile` (адреса клиента — из ответа; добавляя `dns`, `mtu`,
`persistentKeepalive`, `s3=0 s4=0`),
сохраняет и делает активным. При `ok:false` приходит `error` (строка) и **частичный** `result`
с заполненным `log` — журнал шагов надо показать пользователю.

### `ping` (служебная)
Проверка, что ядро живо. Возвращает `{ "pong": true }`.

## Profile

```json
{
  "id": "nl-hostkey",
  "displayName": "Netherlands / HOSTKEY",
  "country": "Netherlands",
  "provider": "HOSTKEY",
  "host": "222.167.208.108",
  "port": 51820,
  "serverPublicKey": "WyhFpvvdzC2OBhpbcRAMzVZXsyWgToZ/4vtVkgBo4F4=",
  "clientVpnAddress": "10.77.0.2",
  "serverVpnAddress": "10.77.0.1",
  "dns": ["1.1.1.1", "8.8.8.8"],
  "mtu": 1420,
  "persistentKeepalive": 25,
  "jc": 5, "jmin": 50, "jmax": 1000,
  "s1": 64, "s2": 128, "s3": 0, "s4": 0,
  "h1": 1000001, "h2": 1000002, "h3": 1000003, "h4": 1000004
}
```

> `s3`/`s4` = 0: userspace-клиент (amneziawg-go v1.0.4) не умеет junk на cookie/transport
> пакетах; сервер приведён к `s3=0 s4=0`, иначе transport-пакеты не сходятся. Обфускацию
> держат `jc`/`s1`/`s2`/`h1..h4`.

## State

```json
{
  "state": "disconnected|connecting|connected|switching|error",
  "profileId": "nl-hostkey",
  "serverName": "Netherlands / HOSTKEY",
  "serverHost": "222.167.208.108",
  "serverPort": 51820,
  "localProxy": "127.0.0.1:8118",
  "pingMs": 47,
  "lastCheckUnix": 1690000000,
  "connectedSinceUnix": 1690000000,
  "lastHandshakeUnix": 1690000000,
  "rxBytes": 12345,
  "txBytes": 6789,
  "lastError": ""
}
```

`pingMs` = `-1`, если проверка не проходила/не прошла. `lastError` пустой, если ошибок нет.
